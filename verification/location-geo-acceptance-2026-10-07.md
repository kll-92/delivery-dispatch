# 骑手位置有效期与 Redis GEO 恢复验收

日期：2026-10-07。仅在已有系统上补充位置有效期和 GEO 恢复，不包含失败派单人工重试、SSE、Testcontainers 或 CI。

## 实现与协作

- Luna High 位置任务：`Rider` 新增 `lastLocationAt`，位置规则、Mapper SQL、幂等迁移和相应测试。
- Luna High GEO 任务：最新数据库读取、每骑手同步锁、token 校验 Lua、启动/定时分批校准，以及有界后台同步队列。
- Luna High 验收任务：独立 HTTP 位置/恢复脚本和容量并发脚本。
- 主 Agent：统一派单前校验、订单行锁等待后的过期回滚、配置与文档、最终代码 Review、真实环境验收和资源清理。

Review 修正：原生 ZSCAN 客户端返回格式与模拟值不同，改为 Lua 返回明确的扁平列表；事务提交回调不再直接获取新事务连接，改为有界后台队列；后台组件的多构造器明确指定 Spring 注入入口，并补真实 Bean 创建测试。最终位置专项只读复核未发现手动、自动或消息派单绕过新鲜度检查。

## 隔离环境

- JDK 21.0.7，MySQL 8.4，Redis 7.4。
- 测试库：`delivery_dispatch_verify_20261007_location`。
- 专用 Redis：`delivery-redis-location-verify`，宿主机端口 16381。
- 测试应用：18082；位置 TTL 20 秒、校准间隔 1000 毫秒、批次预算 10。
- 关闭应用消息发布/消费和待派单补偿，防止后台派单干扰测试夹具。未修改原业务库或停止原 8080 应用。
- 生产默认仍为 TTL 300 秒、间隔 30000 毫秒、批次 100。本次验证不是生产容量基准，也没有重测真实 RocketMQ 投递。

首次故障恢复测试使用批次 2、仅等待 10 秒，恢复窗口不足而失败；按数据规模把验证批次调为 10 后重跑通过。全量校准是多轮扫描，不能在配置任意小批次时保证立即恢复所有数据。

## 实际结果

1. `mvn -q test`：96 tests，0 failures，0 errors，0 skipped。
2. `frontend/npm run build`：TypeScript 与 Vite 构建成功，前端源代码未改动。
3. [位置与恢复报告](location-geo-smoke-2026-10-07.json)：10 组检查通过。
   - 客户端不能伪造上报时间；无坐标创建仍为 NULL。
   - 修改姓名、电话、同坐标资料和启停不刷新位置；专用位置上报同坐标也刷新；资料坐标实际变化才刷新。
   - 附近查询拒绝过期、NULL、未来时间、满载及停用骑手；距离按 MySQL 当前坐标复算。
   - 手动派单拒绝过期位置，允许有效但超过自动半径的骑手。
   - 骑手行锁和订单行锁分别持有 4 秒；两种等待期间位置过期均返回 HTTP 400，订单保持待派单且 rider_id 为 NULL，骑手容量仍为 0。
   - 删除 GEO key 后恢复有效成员，清理过期、NULL、未来时间、满载、停用和数据库不存在的成员，数据库上报时间保持不变。
   - 专用 Redis 停机期间位置上报返回 200 且 MySQL 已提交；重启后 run_id 改变，主动清空重启实例 GEO 后，校准任务再次恢复有效位置，不改变数据库上报时间。
4. [容量并发报告](location-capacity-concurrency-2026-10-07.json)：16 个独立登录会话，100 个不同订单争抢同一新鲜位置骑手；3 个 HTTP 200、97 个 HTTP 400，竞态阶段约 0.389 秒。数据库容量为 3、仅 3 单已分配，其余 97 单未分配；完成 3 单后容量回到 0。
5. [第一阶段真实接口回归](stage1-regression-location-2026-10-07.json)：18 组通过，包括权限、CSRF、DTO、分页、费用修改、删除审计及真实审计写入失败事务回滚。
6. 迁移脚本 `05-rider-location.sql` 在隔离库重复执行成功，列仅存在一次；迁移前历史骑手 `VERIFY-LEGACY` 的位置时间仍为 NULL，未人为制造“新鲜位置”。

## 使用新版本

已有业务库先执行 `src/main/resources/sql/05-rider-location.sql`，再重启后端加载新代码。不要用 `updated_at` 给旧骑手批量补位置时间；旧骑手需要重新上报真实位置，才重新成为可调度候选。此轮没有替用户重启 IDEA 中原有进程，也没有自动提交或推送 Git。

验证用临时应用、Redis 容器、数据库及单独数据库授权在验收后清理；JSON 保留脱敏检查结果，不保留登录密码、Cookie 或 CSRF token。
