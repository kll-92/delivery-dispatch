在派单之前，为什么先引入 Redis？

想象 1,000 名骑手每 5 秒上报一次位置。如果每次都立刻写入 MySQL，会产生大量频繁写入；而派单时又需要快速在附近寻找人。

Redis 存“实时且高频”的骑手位置和接单计数；MySQL 存“正式且需要长期追溯”的订单和骑手基础信息。

你要记住的三句话

  1. Redis 快，因为主要在内存中处理数据。
  2. Redis 有自己的数据结构，不仅是一个简单缓存。
  3. 先用 MySQL 保证正确性，再用 Redis 解决高频读写。
