第六个实战问题：订单该找哪位附近骑手？

订单创建后，不能只按骑手 ID 或当前接单数选择。取货点在北京国贸附近时，几公里外的空闲骑手比几十公里外的空闲骑手更适合。骑手位置会频繁更新，因此本项目用 Redis GEO 保存实时位置索引。

GEO 保存的是什么？

Key:    geo:rider:available
Member: rider:12
Point:  经度 116.4610，纬度 39.9090

Redis GEO 底层是带地理编码分值的 Sorted Set。相同 Member 再次 GEOADD 会更新位置；移除骑手位置使用 ZREM。

实时位置更新

GEOADD geo:rider:available 116.4610 39.9090 rider:12

顺序永远是经度在前、纬度在后。经度范围是 -180 到 180，纬度范围约为 -85.0511 到 85.0511。

查询取货点附近骑手

GEOSEARCH geo:rider:available
  FROMLONLAT 116.4550 39.9080
  BYRADIUS 5 km
  ASC
  COUNT 20
  WITHDIST

含义：以取货点为圆心，找 5 公里内最多 20 位骑手，按距离从近到远返回，并携带距离。

GEO 不是最终调度决策

GEO 只负责快速缩小候选范围。最终还必须检查 MySQL 中的骑手状态、当前订单数和并发占用情况。即：

Redis GEO：附近候选人
  → MySQL：状态/订单量等真实业务数据
  → 调度规则：距离优先，再考虑负载
  → 原子占用：防止多订单抢同一骑手

Redis 官方文档说明：GEOADD 写入经度、纬度、成员，GEOSEARCH 可按圆形或矩形范围搜索，并按距离排序。GEOADD / GEOSEARCH

本课动手目标：先用 redis-cli 手动写入三位骑手位置，再按取货点查询附近骑手；确认语义后再接入 Java。
