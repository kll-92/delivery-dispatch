第十五课：JVM 到底是什么

先给结论：你的项目一直在使用 JVM。每次你在 IDEA 里启动 Spring Boot，实际上都是启动一个 Java 进程，让 JVM 加载并运行你的项目。

先用一句人话理解

JVM 是 Java Virtual Machine，中文叫“Java 虚拟机”。它不是一台新的电脑，而是运行在操作系统里的一个程序，专门负责把 Java 程序跑起来。

可以把它想成一个“Java 专用的运行房间”：你的 Java 代码进入这个房间后，JVM 负责加载代码、分配内存、管理线程、回收不用的对象，并把常用代码优化得更快。

Java 代码是怎样跑起来的

RiderService.java
        ↓ javac 编译
RiderService.class（Java 字节码）
        ↓ JVM 加载并执行
操作系统上的机器指令

你写的 Java 源码不会直接被 macOS 当作机器指令执行。编译器先把它变成比较通用的字节码，JVM 再在当前电脑上运行这些字节码。这也是 Java 能跨操作系统运行的重要原因之一。

JVM 主要负责什么

职责白话解释项目中的例子
加载和执行找到并运行你的类、方法启动 DeliveryDispatchApplication
内存管理给对象和方法准备运行空间Rider、订单对象、JSON 对象
垃圾回收清理已经没人使用的对象请求结束后不再使用的临时对象
线程管理让多个请求、定时任务同时运行Tomcat 请求线程、Outbox 定时发布任务
运行时优化把经常执行的代码优化得更快反复调用的 Service、Mapper 路径

最常听到的三个内存区域

先记简化版，不必一开始背所有 JVM 细节：

  • 堆（Heap）：主要放对象，例如 new Rider() 创建出来的对象。垃圾回收器主要管理这里。
  • 栈（Stack）：每个线程调用方法时使用的临时工作区，保存方法参数、局部变量和调用过程。
  • 元空间（Metaspace）：保存类的结构信息，例如 Spring 扫描到的 Controller、Service 类信息。

不要把“引用”和“对象”混为一谈：方法里的变量更像是指向对象的地址；对象本身通常在堆里。

你的项目到底哪里用到了 JVM

pom.xml 明确要求 Java 21：

<java.version>21</java.version>

启动类中的：

SpringApplication.run(DeliveryDispatchApplication.class, args);

会在 JVM 中启动 Spring Boot。Spring Boot 的内嵌 Tomcat、Controller、Service、Mapper、Redis 客户端和 MySQL 客户端，都在这个 Java 进程里运行。

你之前控制台里看到的：

/Library/Java/JavaVirtualMachines/jdk-21.jdk/Contents/Home/bin/java ...
com.kll.deliverydispatch.DeliveryDispatchApplication

其中的 bin/java 就是启动 JVM 的程序；后面的类名是交给 JVM 运行的 Spring Boot 启动类。

哪些东西不属于这个 JVM

Docker 里的 MySQL 和 Redis 是独立的服务进程。你的 JVM 通过网络连接它们，但它们不是和 Spring Boot 共用同一个 JVM。

Spring Boot + Tomcat —— 在 Java/JVM 进程中
MySQL                 —— 独立数据库服务
Redis                 —— 独立缓存服务

我们现在“用了 JVM”，但还没有“调 JVM”

目前项目使用的是 JVM 默认的内存、垃圾回收、线程和 JIT 优化。我们还没有主动设置堆大小、选择垃圾回收器或编写 GC 日志分析。

Actuator 可以观察 jvm.memory.used、jvm.gc.pause 等现象，但“观察”不等于“自动调优”。先看到问题，再决定是否调整 JVM 参数。

如果你在 IDEA 的启动命令里看到 -XX:TieredStopAtLevel=1，它是开发环境为了更快启动而加的 JVM 参数，不是骑手业务逻辑。

这一课的面试表达

“我们的 Spring Boot 服务运行在 Java 21 的 JVM 上。JVM 负责字节码执行、内存管理、垃圾回收和线程运行。项目目前主要使用 JVM 默认配置，并通过 Actuator 观察 JVM 内存和 GC 指标；还没有做专项的 GC 或堆参数调优。”
