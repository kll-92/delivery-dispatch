# 学习记录：条件更新与骑手名额原子保护

## 本次掌握

- `WHERE` 在 SQL 执行时重新检查业务前提，`SET` 负责在条件满足后修改字段。
- 订单状态条件更新防止旧请求覆盖已经变化的订单状态。
- `tryClaimForOrder` 把“可用且未满载”的检查与接单数加一放进同一条 UPDATE；影响行数 1 表示占用成功，0 表示名额已被其他请求占用或条件不满足。
- `releaseOrderSlot` 用 `current_order_count > 0` 防止负数，并与完成订单更新放在同一个 MySQL 事务中。
- `disableIfIdle` 同时检查可用状态和零接单数，避免停用与新派单互相覆盖。
- 指定字段更新解决的是“旧实体覆盖其他字段”，与条件更新解决的“业务前提已变化”不是同一个问题。
